# 设计要求

充电上限是菜单栏里的电池软件。它按时间段写系统充电上限，需要时把电放到上限，按每一段决定低电量模式，并在窗口上排显示这台 Mac 当时的电池和内存。

## 作息

市电每天 06:00 来，23:30 断。23:30 之后开始写代码，自己会再接一个充电宝。23:30 不是软件里的定时任务，软件不负责断电。

默认两段：

| 时间 | 充电上限 | 高于上限时 | 低电量 |
|---|---|---|---|
| 06:00–20:59 | 80% | 放电到 80% | 不用 |
| 21:00–次日 05:59 | 100% | 不放电 | 仅用电池时开 |

21:00 才把上限放开到 100%。从 80% 补到 100% 是慢的那一段，22:30 才放开往往赶不上 23:30。21:00 到 23:30 大约两个半小时。

这些时间可以改。结束早于开始，表示跨过午夜。没有被任何一段盖住的时间按 100%。时间段不能重叠，最多 12 段。上限只能是 80、85、90、95、100。

## 放电

白天的目的是把电量放到并停在 80% 左右，所以高于上限时要真的放电，不能只停止充电。

苹果自己的充电上限只会停止充电，接着电源时不会放电。真正放电要把电源适配器暂时断开，只能靠写 SMC，需要 root。所以软件带一个放电帮手：一个以 root 运行的系统后台程序，只做断开或接回电源适配器、在没有系统上限的旧系统上停止充电、在 Intel 上写 BCLM 上限、报告状态。它只在用户点「安装放电帮手」时才装，要一次管理员密码。PKG 更新时只会替换已经装过的帮手，不会替没装过的人装。

放电规则写死在帮手和软件两边，互相守着：

- 只有这一段开着「高于上限时放电」，并且当时的原因是时间表，才放电。临时充满、断电前充满、过热保护、空档都不放电。
- 没有漂移时：电量超过上限 3% 才开始放，放到上限就接回电源。之所以留 3%，是因为苹果的上限会停在“几个百分点”之内；如果只留 1%，80 和 82 之间会反复放、反复充。
- 漂移（可选 5% 或 10%）：到上限就开始放，掉到上限下面这么多才接回电源，电量在中间自己漂。只在放电的时间段里生效，不放电时不漂。
- 最低放到 20%，上限设得再低也不会低于它。电量 20% 以下不断开电源。
- 今天不放电：只管当天，过了午夜自动恢复。
- 放电需要的温度信息读不到，也不放（这一条还没有做，列在待办里）。
- 睡眠前一律接回电源。软件退出、崩溃或 2 分钟收不到续期指令，帮手自己接回电源。
- 帮手只认安装它的那个用户，套接字权限 0600，并检查对端 uid。不联网。
- 断开电源适配器后，系统会说“没接电源”。帮手和软件都不能因此半路接回又断开。
- 断电只用一个键：新固件用 `CHIE`，否则用 `CH0I`。同时写两个，一个失败时状态就对不上了。
- 上限由帮手设的（旧系统、Intel），24 小时没有软件续期就恢复原样。软件平时每 5 分钟报一次到。
- 不装帮手、SMC 里没有对应的键时，退回只停止充电或只读，窗口写明。

接通电源但已经充满时，电流可以是 0，这时要显示接通，不要显示成正在充电。

## 低电量

每一段单独选：这段不用、这段一直开、仅用电池时开。默认白天不用，晚上那段仅用电池时开。

系统把电池和电源分成两套开关。只有点「立即应用」，并且和系统现在的值不一样，才弹出 macOS 自己的管理员密码框。密码不经过本软件。到了 06:00 或 21:00 不弹密码；窗口里写「低电量要改，点立即应用」。

管理员密码一共只在两处要：装或卸放电帮手，改低电量。

## 时间怎么选

用小时和分钟两个下拉，外加一个表盘。不让人自己敲时间文字。

## 菜单栏

登录后自动打开，没有程序坞图标。点菜单栏图标打开或关上窗口。开机拉起时带 `--background`，不弹窗口，也不弹更新框。

菜单栏文字参照 FanBar 的上下排列，省横向宽度：上面一行是这一段的上限，下面一行是充电、放电、接通、电池或无电池。两行画在同一张模板图标里，因为菜单栏按钮不保证显示换行。位置用系统的 `autosaveName` 记住。带刘海的 Mac 上，按住 Command 可以把图标拖到刘海两边。没有公开接口能让软件自己跳进刘海，所以另有刘海灵动岛。

刘海灵动岛：在刘海的位置盖一块黑色面板，平时和刘海重合看不见。鼠标移到刘海上，或插拔电源时，面板从刘海里展开，显示电量环、状态、上限、今晚的计划，以及「临时充满」「打开窗口」。可以选在刘海两侧常驻小字（左边上限，右边状态）。没有刘海的屏幕可以选在菜单栏正中虚拟一个。只读鼠标位置，不用辅助功能、屏幕录制或输入监控。

关上窗口后软件继续运行。点「退出」后，这次登录不再改上限；勾了登录启动时，下次登录再打开。

打开之后就会按时间段写充电上限。低电量不在这时写，只在「立即应用」。

从磁盘映像里直接打开不能登记登录启动。装进「应用程序」之后，第一次正常打开会写入登录项。写入时不立刻再启动一个进程，避免菜单栏出现两个图标。

## 上排：电池和内存

数字都从这台 Mac 当时读，不写死。

电池来自 `ioreg` 的 AppleSmartBattery 和 `pmset -g therm`：电量、电流、电压、正在充电还是放电还是接通但没有电流、健康度、标称容量、设计容量、满充容量、循环次数、温度、有没有过热放慢充电。顶层字段是 `"键" = 数字`，电池数据内部是 `"键"=数字`，两种都读。`IsCharging` 可以是 Yes、No、1 或 0。

健康度是标称容量相对出厂设计容量的估算，要标明是估算。`MaxCapacity` 一类字段常常是电量百分比，不能把它当成健康度。温度 3000 表示 30.0°C。读不到内置电池时直接写没有电池，台式机不能崩。

内存来自 `hw.memsize` 和 `host_statistics64`：总容量、估算已用、压力。已用按活跃、联动和压缩页估算，不等于活动监视器的同名栏目。压力高并且正在放电时，才把两件事写在一起。不编一个电池优化分数。

建议句子只能从这些读数推出来：健康度低于 80%、循环用掉设计值的大部分、温度达到 35°C、充过热、接近满电还连着电源、内存压力高。

## 下排：设置

时间段表格、下拉和表盘、这一段的低电量、登录后藏在菜单栏、检查更新、再看引导、卸载、退出、立即应用。

窗口是窄的上下列表，不是左右两栏，也不是网页。文字用系统字体。

上排、下排两层都能折叠，第二层的卡片也能各自折叠，折叠的状态记在本机，收起时标题右边写一句摘要。下排有：时间表、放电帮手、聪明一点、刘海、系统。

电量曲线画过去 16 小时，右边用虚线接上之后几小时的预测：按时间表、断电前充满和放电推算，到断电为止。

## 引导动画

第一次正常打开先播六步引导，画在窗口里，不放视频。看完或跳过之后写入 `guideSeen`，下次不再挡。`--background` 不播。

六步是：放进「应用程序」、菜单栏上下两行、按住 Command 拖到刘海两侧（并说明刘海灵动岛）、管理员密码用在哪里、充电上限看机器、白天放到 80% 就停。

读电池、温度、内存，以及在支持的机器上改充电上限，都不要额外隐私授权。引导里不要求完全磁盘访问、辅助功能、屏幕录制或输入监控。没有一个开关能让普通菜单栏软件变成系统最高权限。要管理员密码的只有装放电帮手和改低电量。

安装包是临时签名，第一次打开如果被系统拦住，在访达里按住 Control 点「打开」。

## 更新和卸载

启动后向 GitHub 发布页查版本。有新版本时，等窗口真正打开并且引导已经结束，再提示。

卸载去掉登录项和本机配置，并删掉「应用程序」里的软件。不把充电上限和低电量改回去。

## 兼容

macOS 13 起可以安装，Apple 芯片和 Intel 各有 PKG 和 DMG。动画和图表在 13 上会少一点（比如充电图标不跳动），功能不少。

Apple 芯片上：macOS 26.4 及更新用系统自带的充电上限；更旧的系统由放电帮手直接停止充电。放电只有 Apple 芯片并且装了帮手才有。Intel 和台式机只读电池、内存、温度，时间表和低电量仍然可用，窗口写明不支持。

## 打包

GitHub Actions 编译、跑不碰真机电池的测试，再上传两种芯片的 PKG 和 DMG；推到 main 时自动发布到 Releases。安装包里是软件，不是源代码。Actions 上的机器没有 MacBook 电池，不能代替自己点「立即应用」之后看「系统设置 → 电池」。

开发时不在这台正在使用的 Mac 上安装，避免改掉现在的充电上限。

## 外观和实时

窗口质感三选一：纯色、磨砂（模糊桌面）、玻璃（macOS 26 起用系统 Liquid Glass，更早的系统退回磨砂），透明度 0 到 70% 可调，改动马上生效，记在设置里。窗口背景由界面自己画，窗口本身是不透明度为零的底。

窗口看得见（没被盖住、没最小化）时每 2 秒读一次电池、内存和系统值，看不见时 30 秒一次；灵动岛展开时也是 2 秒。动画（液体电量盘、电流圆点、实时灯）只在窗口看得见时跑，并跟着“减少动态效果”。

## 性能

窗口没开时几乎不占 CPU：30 秒读一次电池和内存，pmset 要起进程，窗口没开时 10 分钟才读一次；插拔电源、睡眠唤醒、温度状态变化时马上读一次；菜单栏图标只在内容变了才重画；引导动画只在引导里跑，并且跟着“减少动态效果”；刘海灵动岛没打开时不装鼠标监听。

`--bench` 量读系统、画图标、预测、历史写盘各要多久；`--bench-live` 把窗口打开跑 8 秒，量动画和 2 秒刷新占多少 CPU；超过预算就失败。CI 还会让软件空闲 45 秒，看 CPU 和内存。
