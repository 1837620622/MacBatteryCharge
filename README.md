# 充电上限

**保护电池，并且让用户有电。**

Mac 菜单栏里的电池软件。第一个目标不是限制充电，而是让你在需要离开电源的那一刻，尽可能拥有足够的电量。平时按你的作息把上限停在 80% 左右，离电前按这台机器自己的充电速度充到你要的目标电量。免费开源。

> **Ready Before Unplug**：告诉它你什么时候需要用电池，其他的交给它。

**状态：3.0.2。** 在 macOS 26 上用 Swift 和 SwiftUI 重写，并且编译、单元测试、打包都在 CI 里通过。充电上限、放电、Intel 的 BCLM 还没有在真机上完整测过，见 [诚实的限制](#诚实的限制)。

## 三件事

- **日常保护**：平时把上限停在 80% 左右，少让电池长时间满电。
- **准时备电**：按你设的离电时间和离电目标，算出最晚什么时候开始充，尽量赶在离电前充到。
- **异常恢复**：放电时，睡眠前、退出软件，或者帮手两分钟收不到续期，都会把电源接回来；睡眠唤醒后会重新核对系统上限。

## 三种用法

同一套时间表可以按三种方式用，在窗口最上面选：

- **智能（新装默认）**：平时停在日常上限（默认 80%），快要拔电时按你平时拔电的时间自己补到 100%。目标是「随时有电」，同时尽量少在满电里待着。智能模式不主动放电——一边接电源一边掉电和「随时有电」冲突。
- **固定**：严格按时间段执行，每段的上限、放电、漂移、低电量都听你设的。原来用 2.x 的人都落在这里，升级不会替你换掉行为。
- **一直充满**：不管时间表，始终 100%。适合台式机，或者电池已经不太在乎的机器。

## 为什么做

- 出门、断电、换到移动电源前，最怕的是电量不够。软件先按你设的离电时间，算出最晚什么时候开始充，尽量赶在离电前充到你要的目标。
- 平时把上限停在 80% 左右，少让电池长时间满电，对电池寿命有好处。这是顺带的好处，不是第一目标。
- 这里做的是“一整天的计划”：离电前备电、临时充满和每一段的上限放在一起。
- 所有判断都从这台电脑的读数来，不猜，不写死。

## 功能

- **离电前备到目标电量。** 设一个每天离电的时间（默认 23:30）和一个离电目标（默认 100%），软件按这台机器学到的充电速度，算出最晚什么时候开始充，尽量赶在那之前充到。离电目标和每一段的日常上限是两件事：白天停在 80% 的日子，离电目标照样可以设 100%。窗口里的「今晚」一栏写预计几点充满；没接电源时只说「插上电源后约 X 分钟」，不给确定的时刻。速度是学出来的，用得越久越准；学不准时会在窗口里写明。
- **临时充满。** 到下一段开始或拔掉电源前，先放开到 100%。
- **一天的圆盘。** 外圈是时间表，每一段一道弧，颜色深浅就是上限高低；圆盘里的水面是现在的电量；圆点是现在的时间。点外圈一段，就打开它的设置。
- **时间段。** 每段一个上限（80、85、90、95、100），可以选放电、漂移、低电量模式。时间用小时、分钟下拉或表盘选，不用自己敲。
- **放电（默认关）。** 在你打开的那一段里，超过上限 3% 才开始放，放到上限就接回电源。需要放电帮手，见下面。默认不放电：只限制充电的人不会在不知情的时候看着电量往下掉。
- **漂移。** 放电的时段里可以选“掉 5%”或“掉 10%”：电量到上限就开始放，掉到下面这么多才接电，在中间自己漂，少在满电里待着。
- **今天不放电。** 只管今天，过了午夜自动恢复。
- **过热保护。** 电池传感器读到 35°C 时先停在 80%，降到 33°C 再恢复。这两个数是我们选的保守值，不是苹果规定的电池停充温度。苹果公布的是环境温度 10–35°C。
- **预测曲线。** 过去 16 小时的电量，加上之后几小时的预测。
- **刘海灵动岛。** 点一下刘海，从刘海里展开电量、上限和今晚的计划，再点一下收回去。插拔电源时也会自己弹出来。可以选在刘海两侧常驻一行小字。没有刘海的屏幕也能虚拟一个。
- **外观。** 纯色、磨砂、玻璃三种质感，透明度可调，改动马上生效。玻璃在 macOS 26 上用系统的 Liquid Glass，更早的系统自动用磨砂。
- **读数。** 功率、温度、健康（估算）、循环次数、电源、低电量。读数每 2 秒刷新一次（窗口看得见时），看不见时 30 秒。
- **更新。** 窗口里下载、校验 SHA-256、装好后自动重新打开。登录时后台启动不查更新，也不弹窗。
- **长期记录。** 像健康 App 那样，每天一行：最低和最高电量、接着电源多久、用电池多久、挂满多久、第一次拔电的时间和最热温度。留一年（400 天）。窗口里画成每天一根柱：接电源是一色，用电池是另一色。这些记录只在本机 `journal.json` 里。
- **温馨提醒。** 记录够三天之后，它会看着记录说话：这一周有几天挂在满电、你平时大约几点拔电源、这周几乎一直插着电源、最热到多少度、30 天健康掉了几个点、一周循环涨了多少。每一条都对应一个具体数字，不写空话。
- **多语言。** 简体中文和英文。默认跟随系统，也可以在窗口里直接选，改完立刻生效。
- **崩溃和错误日志。** 自己记日志：崩溃时的异常名、说明和调用栈，以及写上限失败这类错误。日志在 `~/Library/Application Support/MacBatteryCharge/Logs`，只留最近几份，每份 512 KB，路径里的用户名会换成 `~`。
- **反馈问题。** 系统卡片里的「反馈问题」直接打开 GitHub 新建 issue，标题、诊断信息和最近 120 行日志都已经填好，写完现象就能提交。日志太长就复制到剪贴板再开空页面，不会丢。
- **诊断。** 「复制诊断」一键复制这台机器的读数、上限由谁执行和帮手状态。不含账号和个人信息。

## 支持的机器

| 机器 | 系统 | 充电上限 | 放电 |
|---|---|---|---|
| Apple 芯片 | macOS 26.4 或更新 | 系统自带的上限 | 需要放电帮手 |
| Apple 芯片 | macOS 13 到 26.3 | 放电帮手停止充电 | 需要放电帮手 |
| Intel（有 BCLM） | macOS 13 或更新 | 放电帮手写 BCLM | 需要放电帮手，且机器要有断电的键 |
| 其他 | — | 只读：电池、温度 | 不支持 |

macOS 27 和 Intel 上的 BCLM 还没有在真机上验证。

有少数机器两种路都不通：系统没有充电上限接口，固件又只允许系统自己管（帮手探不到可写的键）。这种机器上窗口会直接写明「这台 Mac 的上限没人执行」，诊断里也会写「上限执行者：没有人」，不会假装在护电池。

## 安装

从 [Releases](https://github.com/1837620622/MacBatteryCharge/releases) 下载对应芯片的文件：

- Apple 芯片：`MacBatteryCharge-3.0.2-arm64.pkg`（或 `.dmg`）
- Intel：`MacBatteryCharge-3.0.2-intel.pkg`（或 `.dmg`）

PKG 会装到“应用程序”。DMG 打开后把软件拖进“应用程序”。从磁盘映像直接打开，登录时不会自己启动，窗口里会提示放进“应用程序”。

软件没有经过 Apple 公证。第一次打开如果被系统拦下，到「系统设置 → 隐私与安全性」，在下面点「仍要打开」。

第一次打开会看六步引导。

## 权限和密码

- 读电池、温度：不需要任何授权。
- 安装放电帮手：一次管理员密码，系统自己的密码框。
- 改低电量模式：只在点「立即应用」、并且和系统现在不一样时，弹一次系统密码框。
- 不需要完全磁盘访问、辅助功能、屏幕录制或输入监控。刘海灵动岛只用鼠标位置和点击。

## 隐私和联网

- 不需要账户，不上传电池数据，不采集使用习惯。
- 会联网的只有两处：「自动检查更新」（默认打开窗口时每天最多查一次 GitHub 上的最新版本号，可以在设置里关闭），以及你主动下载更新的时候。

## 放电帮手

Mac 自己的充电上限只会停止充电，不会在接着电源时放电。要把电放到 80%，就得暂时断开电源适配器，这要写系统的 SMC，需要 root 权限。所以有一个小程序，以 root 身份运行：

- 装在 `/Library/PrivilegedHelperTools`，由 launchd 管理，开机自启。
- 只做这几件事：断开或接回电源适配器（SMC 的 `CHIE` 或 `CH0I`）；旧系统上停止或恢复充电（`CH0B`/`CH0C` 或 `CHTE`）；Intel 上写 `BCLM` 上限。它不会写别的键。
- 只认安装它的那个用户：套接字权限 0600，并检查对端的用户号。不联网，不读任何文件。
- 安全规则：电量 20% 以下不断开电源；睡眠前一律接回电源；软件退出，或者 2 分钟收不到软件的续期，就接回电源。
- 上限由帮手设的（旧系统、Intel），24 小时收不到软件的续期就恢复原样。软件每 5 分钟报一次到。

卸载：窗口里点「卸载」，或者在放电帮手卡片里卸载。卸载时会先把电源接回来。

## 诚实的限制

- **离电前备电不是保证。** 离电时间临时提前，或者充电变慢（比如换了移动电源），都可能到点还没充到目标。学出来的速度只是估计。
- **苹果的原生上限不是精确的。** 官方说它会停在“几个百分点”之内，并且会“偶尔”充到 100%，为了让电量估算准确。软件阻止不了这一点，也没有办法知道它什么时候发生。
- **没有校准功能。** 校准要从 100% 放到很低再充回去。我们的设计是不深放，所以不做。
- **白天放电时用的是电池。** 插着电源，电池也在降，这是设计如此。这个功能默认关闭，要你自己打开。
- **还没有在真机上完整测过。** CI 能编译、跑单元测试、打包，但不能写真的硬件。发布后请在你自己的 Mac 上测：白天能不能放到 80；漂移是否按设定；睡眠唤醒后是否接回电源；退出后上限是否保留；有 Intel 机器的话测一下 BCLM。
- 真机测试的清单和报告模板见 [docs/真机测试.md](docs/真机测试.md)。
- 漂移的下限是近似的。苹果的原生上限要掉超过 5% 才续充，所以“掉 5%”在有原生上限的机器上可能会落到 74% 左右。
- 温度来自系统的电池传感器，和苹果的温度显示可能有差别。

## 和别的软件比

完整的对比和我们读过的资料，见 [docs/调研.md](docs/调研.md)。简单说：

- 免费，开源。
- 有“一天的计划”：每段独立的上限、放电、漂移和低电量。
- 有离电前备电，按这台机器自己的速度算，离电目标和日常上限分开设。
- 支持 Intel（BCLM）和旧系统（帮手停充），不是只支持新系统。

## 开发

```bash
swift test                                            # 逻辑测试，不碰硬件
bash packaging/build.sh                               # 测试、编译两种芯片、打 PKG 和 DMG（只打包，不安装）
.build/release/MacBatteryCharge --snapshot snapshots  # 用假数据输出界面截图
.build/release/MacBatteryCharge --bench               # 逻辑和读数的耗时预算
.build/release/MacBatteryCharge --bench-live          # 窗口打开时的 CPU 预算
```

Actions 在 macOS 上跑同样的步骤，还会让软件空闲 45 秒看 CPU 和内存，并把截图作为附件上传。推到 `main` 时自动发布到 Releases。
